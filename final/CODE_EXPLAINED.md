## 1. `run_final.py` — 내 모델 (q_joint)

코드는 9개 섹션(주석 `# 1.` ~ `# 9.`)으로 나뉘어 있다.

### 1-1. 데이터 불러오기 (섹션 1)

```python
v['lv'] = np.log1p(v.view_5d)
L = v[v.is_shorts == 0]   # 롱폼
S = v[v.is_shorts == 1]   # 쇼츠
```

- **`log1p` 변환을 쓴 이유**: 조회수는 채널마다 수십 회에서 수백만 회까지 차이가 크다(두꺼운 꼬리). 로그로 바꾸면 "몇 배"를 "몇 만큼"으로 다룰 수 있고, 정답 규칙 자체도 로그 차이로 정의된다. 1을 더하는 건 조회수 0일 때 log(0)을 피하려는 것이다.
- **롱폼/쇼츠 분리**: 라벨은 롱폼만으로 정해진다. 쇼츠는 피처(쇼츠 비중)로만 쓴다.
- `TEST_D`(09-01)와 `PREV_D`(08-25, 테스트 직전의 공식 정답 날짜)를 `sample_submission`과 `train_labels`에서 **자동으로** 읽는다. 그래서 하드코딩 없이 연습(F=18)과 본선(F=26)에서 같은 코드가 돌아간다.

### 1-2. 라벨 재구성 (섹션 2: `past`, `partial_s`, `label`)

```python
def past(d):      # d 이전 롱폼 view_5d 중앙값 (3편 이상 & 중앙값 100 이상만 = 채점 대상)
def partial_s(d, end):  # [d, end) 영상만으로 점수 s 계산
    o['s'] = np.log1p(o.fm.fillna(0)) - np.log1p(o.pm)
def label(d, f):  # s 상위 20% = 1
    return (o.s >= o.s.quantile(.8)).astype(int)
```

- **왜 필요한가**: 공식 정답은 08-11과 08-25 **두 날짜뿐**이다. 이것만으로는 학습 데이터가 너무 적다.
- **방법**: 공개된 정답 정의(과거·미래 롱폼 중앙값의 로그 차이, 그날 상위 20%)를 그대로 코드로 구현했다. 미래 창에 영상이 없으면 미래 점수 0이라 s가 매우 작아진다.
- **검증**: 재구성한 08-11 라벨과 공식 08-11 정답이 **98.5% 일치**했다. 나머지 1.5%는 날짜 경계 시각이나 채점 대상 조건의 미세한 차이로 추정한다(`--label_diag`로 원인 분해 가능).
- **결과**: 07-18부터 **매일의 학습 라벨**을 만들 수 있게 됐다.
- **`partial_s`가 핵심 도구인 이유**: `end`를 `d + F`보다 이르게 주면 "미래 창의 앞부분만 본 점수"가 된다. 이 함수 하나로 정식 라벨(섹션 2), 직전 정답의 관측 부분(섹션 4), 소프트 라벨의 부분 관측(섹션 7)을 모두 계산한다.

### 1-4. 직전 정답 역추론 피처 (섹션 4: `add_lag`) — 가장 강한 단서

```python
'lag'       : 7일 전 기준일의 정답 (테스트에서는 공식 08-25 정답)
'lagobs_rk' : 그 정답의 미래 창 중 이미 관측된 부분 [D-7, D)의 점수 순위
X['lag_x_obs']   = X.lag * (1 - X.lagobs_rk)     # 정답 1인데 관측 부분이 약했다
X['nolag_x_obs'] = (1 - X.lag) * X.lagobs_rk     # 정답 0인데 관측 부분이 강했다
```

- **날짜로 설명**: 08-25 정답은 **08-25 ~ 09-11(18일)** 영상으로 매겨졌다. 우리 데이터는 08-31에서 끝나서 **08-25 ~ 08-31만 보이고 09-01 ~ 09-11은 안 보인다.** 이 안 보이는 구간이 테스트 창(09-01 ~ 09-26)과 겹친다.
- **역추론**: "정답은 1인데 보이는 앞부분은 약했다"면 "안 보이는 뒷부분(= 9월 초)이 강했다"는 뜻이다. 그래서 `lag_x_obs`가 크면 테스트에서도 1일 가능성이 높다. `nolag_x_obs`는 반대 방향이다.
- **학습 때는** 재구성 라벨로 7일 전 정답을 만들고, **테스트 때만** 공식 08-25 정답으로 바꿔 넣는다.
- `--lag1feat`(채택): 관측 구간이 "1편 히트"인지 "여러 편 고른 상승"인지 구분하는 `obs_conc`(최고 조회수 / 합), `obs_nrise`(과거 중앙값을 넘은 편수)를 추가했다. 오답 분석에서 **상위권 오답의 74%가 lag=1인데 안 오른 채널**이었는데, 이걸 겨냥한 피처다.

### 1-5. 구조 확률 `struct_p` (섹션 5, `--mode latest`)

```
P(Rising) = Σ_n Pois(n; 업로드율 × F) · P(Binom(n, p) ≥ n//2 + 1)
p = 1 − Φ((문턱 − μ) / σ)    # 영상 한 편이 문턱을 넘을 확률 (μ, σ는 최근 영상 가중)
```

- **의미**: 정답 규칙 "미래 n편의 **중앙값**이 문턱을 넘는가"를 확률로 직접 계산한 값이다. n편 중 과반이 문턱을 넘어야 중앙값이 넘는다.
- **왜**: 편수가 적고 σ가 큰 채널은 운으로도 상위 20%에 들기 쉽다. 피처 몇 개로는 표현이 어려운 이 비선형 구조를 공식으로 넣었다.
- 문턱은 그날 평균 확률이 0.2가 되도록 맞춘다(정답 비율 20%).

### 1-6. 전처리 (섹션 6: 순위 변환 + 결측)

1. **날짜별 백분위 순위**(`rk_*`): 정답이 "그날 상위 20%"라는 **상대 기준**이라, 피처도 "그날 몇 등인가"로 바꿨다. 8월 말 조회수 급등처럼 날짜마다 분포가 바뀌어도 기준이 흔들리지 않는다.
2. **결측 지시변수** `na_lag, na_m3, na_m7, na_subs, na_m14_old`: 결측은 우연이 아니다. `m3` 결측은 "최근 3일 업로드 없음"을 뜻한다. 결측 여부를 다른 변수로 예측하면 AUC 0.82~1.00이 나와 **MCAR(완전 무작위 결측)가 아니다.** 그래서 "결측이었다"는 사실 자체를 정보로 남긴다.
3. **MICE**(`IterativeImputer`): 다른 피처로 빈 값을 예측해 채운다. **학습 데이터로만 적합**하고 같은 변환을 테스트에 적용한다(누수 방지).

### 1-7. 생존분석 소프트 라벨 (섹션 7) — 점수를 가장 크게 올린 부분

#### 문제: 미래가 잘린 기준일

- 정답에는 기준일부터 **26일치 미래**가 필요한데, 데이터는 **08-31**에 끝난다.
- 그래서 **08-06 이후** 기준일은 미래가 중간에 잘린다. 예를 들어 08-20은 26일 중 12일(08-20 ~ 08-31)만 보인다.
- 사건이 일어났는지 아직 모르는 **우측 중도절단(right censoring)**과 같은 구조다.
- 이 날짜를 버리면 **가장 최근 패턴**을 잃는다. 분포가 빠르게 변하는 데이터라 손실이 크다.

#### 해결: q 모형 → 소프트 라벨

```python
def qmodel(k, C):            # 기본: 관측일 k별 모형
    for d in 정답이_확정된_과거_날짜:
        Z = qfeat(d, d + k*DAY)        # 일부러 앞 k일만 본 정보
        Z['y'] = label(d, F)           # 진짜 최종 정답
    LogisticRegression().fit(Z, y)     # → q = P(최종 1 | 앞 k일 관측)

def train_set(C):
    (a) 정답 확정된 날:  y=정답, w=1
    (b) 잘린 날:         y=1, w=q·k/F   +   y=0, w=(1−q)·k/F
```

1. **q 모형 학습**: 정답이 **확정된** 과거 날짜를 **일부러 앞 k일만 남기고 잘라서**, 그 부분 정보로 최종 정답을 맞히는 작은 로지스틱을 학습한다.
   - 입력(`qfeat`): 앞 k일 부분 점수의 순위 `rk`, 앞부분에 영상이 있었는지 `has`
   - `--q_x`: 평소 조회수 순위, 업로드율, lag 같은 채널 특성 추가 → q = E[y | 부분정보, x]
2. **잘린 날에 적용**: 실제 잘린 기준일의 채널마다 q를 구한다.
3. **두 줄 복제**: 같은 채널을 (정답 1, 가중치 q)와 (정답 0, 가중치 1−q)로 넣는다.
4. **`--soft_k`**: 관측일이 짧을수록 덜 믿도록 가중치에 k/F를 곱한다.

#### 통계적 의미

- 모르는 정답 y를 **관측된 정보 조건부 기댓값** E[y | 부분 관측]으로 대체하는 것이다. **EM 알고리즘의 E-step**과 같다.
- 가중 로지스틱 손실에서 (y=1, w=q) + (y=0, w=1−q)는 −[q·log p + (1−q)·log(1−p)], 즉 **소프트 타깃 q에 대한 교차 엔트로피**와 정확히 같다.
- 하드 라벨로 단정하면(0 또는 1) 오류가 섞이고, 버리면 정보를 잃는다. 소프트 라벨은 **불확실한 만큼만** 반영한다.
- 효과: 예선(연습 리더보드) **0.68 → 0.76**.

#### `--q_joint` (최종 사용): 통합 q 모형

```python
def qmodel_joint(C):
    for d, k in 과거날짜 × range(3, F):
        Z = qfeat(d, d+k)
        Z['kfrac'] = k / F                       # 얼마나 봤는지
        Z['kf_qconc'] = kfrac * q_conc           # × 본 상승의 질
        Z['kf_qnrise'] = kfrac * q_nrise
```

- k별로 따로 학습하던 q 모형을, **k/F(관측 비율)를 입력**으로 하는 하나의 모형으로 합쳤다. 짧은 k에서도 정보를 공유하고, 학습 예제가 많아 안정적이다.
- `--lag1q`로 넣은 관측-질 신호(`q_conc`, `q_nrise`, `q_lag`)와 kfrac의 **상호작용**을 넣었다. "얼마나 봤는지"와 "본 상승의 질"이 함께 q를 결정하게 한 설계다.
- 단독으로는 효과가 없던 `--q_uni`, `--q_em`과 달리, `--lag1q`와 결합해서 개선됐다.

#### `intervals` (latest 모드): 구간 중도절단

- 관측된 m편과 아직 안 올라온 최대 u편(포아송 90% 지점)이 있을 때, 최종 중앙값이 가질 수 있는 **하한 L / 상한 R**을 순서통계량으로 계산한다.
- 최종 점수를 **[L, R] 구간 중도절단**으로 본 것이고, L·R의 순위를 q 모형 입력으로 넣는다.

### 1-8. 모델 (섹션 8: `fit_predict`)

```python
sw = tr.w * 0.5 ** ((tr.D.max() - tr.D).days / 7)     # 소프트 라벨 가중 × 최근일 가중
LogisticRegression(C=A.C).fit(StandardScaler(a), y, sample_weight=sw)
```

- **왜 로지스틱인가**
  1. 채널 약 700개가 날짜만 바꿔 반복되는 데이터라 **독립 정보가 적다.** LightGBM은 노이즈를 외워 시간 검증에서 −0.03 ~ −0.07 떨어졌다.
  2. 라벨 노이즈가 크다. 미래 몇 편의 중앙값이라 우연의 영향이 크다.
  3. 순위 변환 후 신호가 단조·가법적이다.
  4. **소프트 라벨 가중치를 정확히 받는다.**
- **강한 L2 규제**: `C=0.015`(latest) / `0.1`(lb7627). `StandardScaler`로 피처 크기를 맞춰 규제가 공평하게 걸리게 했다.
- **최근일 가중**(반감기 7일): 8월 말로 갈수록 분포가 바뀌어서(문턱 0.25 → 0.68) 최근 패턴을 더 믿는다.

### 1-9. 검증 (섹션 9: `--validate`)

- **시간 기반 검증**: "데이터가 검증일 vd에 끝난다"고 가정하고, 소프트 라벨과 q 모형까지 **전부 다시 만든 뒤** vd의 정답을 맞힌다. 실제 본선 상황을 그대로 재현하는 방식이다.
- **KFold를 쓰지 않은 이유**: 같은 채널이 인접 날짜에 반복되고 미래 창이 겹친다. KFold로 섞으면 학습과 검증에 같은 정보가 들어가 **0.65로 부풀려진다**(정직한 값은 0.40 ~ 0.57).
- **18일 창을 대리 지표로 쓴 이유**: 26일 창은 데이터가 07-10에 시작해서 확정 라벨로 검증할 수 없다. 그래서 vd = 08-06 ~ 08-14(9일)의 18일 창으로 검증했다.
- **채택 기준**: 9일 평균 AP가 오르고, **대부분의 날 개선**되고, 큰 하락이 없어야 채택한다.
- 검증 +0.009는 리더보드에서 대략 +0.002로 줄어들어 반영됐다(검증 9일이 서로 겹쳐 독립이 아니고, LB 표준오차가 약 0.03이다).

## 2. `sim.py` / `run_sim.py` — 팀원의 구조 시뮬레이션

> 팀원 코드다. 블렌딩 설명에 필요한 범위만 정리했다.

1. **현재 수준 추정**: 채널별 로그 조회수에 **강건 칼만 필터**(local level)를 적용해 "지금의 평소 수준"을 추정한다.
2. **08-25 ~ 27 급등 반영**(`fit_boost`): 플랫폼 전체 조회수 급등 폭을 채널 규모별 직선으로 추정해 미래 영상에 더한다.
3. **미래 모의 생성**: 업로드 수는 포아송-감마(과분산), 조회수 잔차는 t분포로 **수천 번(S=8000)** 생성한다.
4. **정답 산식 그대로 계산**: 생성한 미래로 중앙값과 성장 점수를 구하고, 전체 상위 20% 문턱을 넘을 확률 p를 계산한다.
5. **08-25 정답으로 조건부 가중**: 생성된 시나리오 중 08-25 공식 정답과 맞는 것에 가중치를 준다(soft conditioning).

- `run_sim.py`는 sim.py의 데이터 경로만 바꿔 실행하고 `sim_p.csv`를 저장하는 래퍼다.
- **의미**: 내 모델이 "과거 피처 → 정답"을 **판별**적으로 학습한다면, sim은 "미래를 **생성**해서 규칙대로 채점"한다. 구조가 완전히 달라서 블렌딩 효과가 크다.

## 3. T01 (팀원, ranklearn)

- 순위 자체를 학습하는 랭킹 모델이다. 단독 LB는 0.7032다.
- sim 계열과의 순위 상관이 0.855로 낮다. 즉 **다른 정보**를 갖고 있어서 블렌딩 재료로 쓴다.

## 4. 블렌딩 스크립트

### 4-1. 공통 공식

```python
score = Σ w_i · rankpct(src_i)       # 각 모델 출력을 0~1 백분위 순위로 바꿔 가중합
rr    = rankpct(score)
pred  = 1 / (1 + exp(-8 · (rr − 0.8)))
```

- **왜 순위인가**: PR-AUC는 **순위만** 평가한다. 모델마다 확률 스케일이 달라도 순위로 바꾸면 공정하게 섞을 수 있다.
- **마지막 로지스틱 변환**: 순서를 보존하는 단조 변환이라 점수는 변하지 않는다. 제출 범위 0 ~ 1을 보장하려는 장치다.

| 파일 | 하는 일 | 결과 |
|---|---|---|
| `make_v2.py` | sim 0.8 + T01 0.2 → `mate.csv` (BEST_v2) | LB 0.7395 |
| `blend_all.py` | mate 0.9 + qjoint 0.1 → `blend_90` | LB 0.7412 |
| `blend_pro.py` | mate / mate_v3(sim 단독) / qjoint 3중 그리드 | 후보 생성 |
| `blend_t01.py` | mate 0.7 + T01 0.2 + qjoint 0.1 → `try_shot2` | 최종 블렌드 |
| `blend_aggr.py` | T01 비중 확대, 상위권만 재배치, 비선형 결합 등 공격적 후보 | 미채택 |

### 4-2. 비중을 정한 논리

- **단독 성능이 가장 높은 모델(mate)을 주축**으로 둔다.
- 순위 상관이 낮은(= 다른 정보를 가진) 모델을 **소량** 섞는다. q_joint는 판별 모델이라 sim과 오차 구조가 다르다.
- try_shot2는 blend_90 대비 상위 139위 경계에서 4개를 바꿨다. 08-25 정답 0 채널 4개를 빼고, 정답 1 채널 3개와 0 채널 1개를 넣었다. 08-25 정답 1 채널의 다음 양성률이 약 50%로, 0 채널(약 11%)보다 높아서 기대값이 플러스인 교체였다.

## 6. 해석 (SHAP, 내 로지스틱 모델 기준)

- 선형 모델이라 SHAP 값은 **계수 × (표준화된 값 − 평균)**으로 정확히 계산된다(LinearExplainer). 블렌드 전체가 아니라 **내 모델의 해석**이다.

| 변수 | 방향 | 해석 |
|---|---|---|
| `rk_past_med` | − (가장 큼) | **평균 회귀**: 평소가 높은 채널은 더 크게 뜨기 어렵다 |
| `lag` | + | 직전 정답 1이면 다음에도 1일 가능성이 높다(지속성 + 창 겹침) |
| `rk_struct_p` | + | 미래 n편 중 과반이 문턱을 넘을 확률 |
| `lag_x_obs` | + (꼬리가 김) | 직전 정답 1인데 관측 부분이 약했다 → 9월 초가 강했다. 해당 채널에서만 크게 작동한다 |
| `nolag_x_obs` | − | 직전 정답 0인데 관측 부분이 강했다 → 뒷부분이 약했다 |
| `rk_subs`, `rk_past_rel_subs` | − | 큰 채널일수록 덜 오른다 |
| `rk_upl_rate` | − | `struct_p` 등이 업로드 효과를 이미 담고 있어, **조건부로는** 업로드만 많은 채널은 중앙값이 잘 안 움직인다 |

- **의미**: 모델이 정답 규칙의 구조(평균 회귀, 중앙값 규칙, 직전 정답의 역추론)를 따라 예측한다. 엉뚱한 변수에 기대지 않는다는 근거다.

## 7. 전문가 질의응답 대비

**Q. 생존분석이라면서 왜 Cox 모형이나 생존함수를 쓰지 않았나?**
사건 **시간**이 아니라 **중도절단된 라벨을 학습에 어떻게 쓰느냐**가 문제였다. 잘린 관측을 버리지 않고 조건부 확률로 살리는 생존분석의 핵심 아이디어를 분류 문제에 옮겼다. RSF, ICRF, Deep GP 구간중도절단도 시도했지만, 데이터가 작고 노이즈가 커서 로지스틱보다 낮았다.

**Q. 우측 중도절단을 정확히 어떻게 처리했나?**
① 정답이 확정된 과거 날짜를 앞 k일만 남기고 자른다. ② 부분 점수 순위와 채널 특성으로 최종 정답을 맞히는 q 모형을 학습한다(최종은 k/F를 입력으로 넣은 통합 모형). ③ 잘린 날짜에 적용해 q를 구한다. ④ (y=1, w=q·k/F) + (y=0, w=(1−q)·k/F) 두 줄로 넣는다. ⑤ 확정된 날(w=1)과 합쳐 가중 로지스틱으로 학습한다.

**Q. 소프트 라벨이 하드 라벨보다 나은 이론적 근거는?**
가중 로지스틱에서 두 줄 복제는 소프트 타깃 q에 대한 교차 엔트로피와 같다. 모르는 y를 E[y | 관측]으로 대체하는 EM의 E-step이고, 기댓값으로 바꾼 손실은 분산이 줄어든다(Rao-Blackwell 직관). 하드 라벨은 오분류를 섞고, 제거는 정보를 버린다.

**Q. q 모형에 누수는 없나?**
q 모형은 정답이 **이미 확정된** 날짜로만 학습한다. 입력은 기준일 이후 관측된 k일과 그 이전 정보뿐이다. 검증 때도 "데이터가 검증일에 끝난다"고 놓고 q 모형까지 다시 만들었다.

**Q. 왜 로지스틱인가? 트리 모델이 더 강하지 않나?**
채널 약 700개가 반복되는 데이터라 독립 정보가 적고, 라벨은 미래 몇 편의 중앙값이라 노이즈가 크다. LightGBM은 시간 검증에서 −0.03 ~ −0.07 떨어졌다. 순위 변환 후 신호가 단조·가법적이라 선형으로 충분했고, 로지스틱은 소프트 라벨 가중치를 정확히 받는다.

**Q. 98.5% 일치라면 1.5%는?**
날짜 경계 시각(UTC), 채점 대상 조건, 측정이 덜 끝난 최근 영상 등으로 추정한다(`--label_diag`로 분해 가능). 교정 플래그(`--label_fix`)는 성능에 영향이 없었다. 학습 라벨 노이즈 수준이다.

**Q. 왜 KFold를 쓰지 않았나?**
같은 채널이 인접 날짜에 반복되고 미래 창이 겹쳐서, 섞으면 0.65로 부풀려진다(정직한 값은 0.40 ~ 0.57). 실제 상황처럼 "데이터가 검증일에 끝난다"고 놓는 시간 기반 검증만 썼다.

**Q. 26일 창을 직접 검증할 수 없는데 18일 창 검증을 믿을 수 있나?**
대리 지표다. 18일, 26일, 28일 설정의 테스트 순위가 거의 같았고, 검증에서 오른 설정이 LB에서도 같은 방향으로 올랐다. 다만 크기는 약 1/4로 줄어서 반영됐다. 최종 규칙은 예외적으로 **26일 창으로 직접 백테스트**했다(07-25 ~ 08-05는 26일 창 정답까지 계산 가능).

**Q. 마지막 규칙은 리더보드에 과적합한 것 아닌가?**
리더보드를 보고 맞춘 게 아니다. **테스트와 같은 구조의 과거 12개 기준일로 먼저 검증**(양성률 77.5%)한 뒤 적용했다. 같은 방식으로 검증해 틀린 규칙("초반 강세 + 정답 0 → 하위")은 버렸다.

**Q. 0.7412 → 0.7523 중 규칙의 기여는?**
비중 조정(9:1 → 7:2:1)과 규칙을 **동시에** 적용해 제출했기 때문에 정확한 분리는 불가능하다. 규칙만 단독으로 백테스트하면 sim 기준 +0.007이었다.

**Q. 08-25 공식 정답을 피처와 규칙에 쓴 건 누수 아닌가?**
운영진이 제공한 `train_labels`에 들어 있는 학습 정보다. 테스트 기준일(09-01) 이전에 공개된 값이고, 대회 설계상 "직전 정답"으로 쓰도록 주어진 정보다. 업로드 수도 09-01 이전 데이터만 쓴다.

**Q. 외부 데이터는?**
쓰지 않았다. 배포된 `video_5d_views`, `channel_snapshots`, `train_labels`, `sample_submission`만 썼다. 게임, Steam, IGDB 데이터도 시도했지만 신호가 거의 없어서 최종에는 넣지 않았다.

**Q. 08-25 ~ 27 조회수 급등은 어떻게 다뤘나?**
내 모델은 **날짜별 순위 변환**으로 급등에 따른 분포 이동을 흡수했다(정답 자체가 그날의 상대 순위). 팀원 sim은 급등 폭을 채널 규모별로 직접 추정해 미래에 더했다. 두 접근이 달라서 블렌딩 효과가 생겼다.

**Q. 한계와 다음 단계는?**
① 18일 창 대리 검증의 한계. ② 블렌드 비중을 검증으로 최적화하지 못했다(리더보드 확인 횟수 제한). ③ 블렌드와 규칙의 기여 분리. ④ 노트북이 블렌드 이전 단계는 내장 결과를 쓴다. 다음 단계는 sim 출력을 q 모형 입력으로 쓰는 **스태킹**, 그리고 26일 창 백테스트로 비중을 정하는 것이다.
